<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| App -> Go Backend REST (/api/*) | Local HTTP loopback IPC; untrusted session/window/pane data crosses here |
| Client Input -> POST /api/sessions | User-supplied session name, cwd, command strings |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering / Command Injection | `backend-client::validation` | medium | mitigate | Validate session names strictly client-side against regex `^[A-Za-z0-9][A-Za-z0-9_./-]*$` and reject colons, dots, leading `$` to prevent command injection into tmux |
| T-02-02 | Denial of Service | `backend-client::models` (serde) | low | mitigate | Use typed serde structs with `#[serde(default)]` so null or unexpected JSON fields do not crash deserialization |
| T-02-03 | Denial of Service / Race Condition | `AppState::poll_generation` | medium | mitigate | Generation guard counter discards stale/delayed HTTP responses, preventing state corruption from network races |
| T-02-SC | Tampering | Cargo dependencies | high | mitigate | All dependencies pinned to exact versions in workspace Cargo.toml and Cargo.lock |
</threat_model>
