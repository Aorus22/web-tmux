## Interaction Contract

1. **Sidebar Toggle**:
   - Title-bar sidebar toggle button (SHELL-03) snaps sidebar width binary between **240px** (`w-60`) and **0px** (`w-0`). No CSS animation / slide transition (documented deviation).
2. **Session Tree Expansion & Selection**:
   - Clicking ChevronRight toggles expansion state in `HashSet<String>` for that session.
   - Clicking the session row body selects the session as `activeSession` and renders the workspace tab.
   - Clicking window/pane sub-rows currently highlights context (tab switching arrives Phase 3).
3. **Polling & Refresh Semantics**:
   - `tokio::time::interval(Duration::from_millis(1500))` triggers background GET `/api/sessions` to fetch `TmuxTree`.
   - Clicking the `RefreshCw` header button triggers an immediate fetch and restarts the interval.
   - External tmux CLI changes appear automatically within ≤ 1500ms (SESS-06).
4. **Create Session Flow**:
   - Opened via `Plus` icon in sidebar, `Create Session` button on EmptyState, or shortcut.
   - Form autofocuses on Name input.
   - Clicking "Browse…" opens native folder picker (`App::prompt_for_paths`); selected path is written to `cwd`.
   - Submitting sends `POST /api/sessions { name, cwd, initial_command }`.
   - On success: closes dialog, triggers immediate tree refresh, and sets the newly created session active.
   - On failure: displays inline backend error message without closing dialog.
5. **Escape & Dismiss**:
   - Pressing `Escape` or clicking modal backdrop dismisses `CreateSessionDialog` and clears form fields.

## Assumptions

*(User is away; discuss decisions auto-accepted. Each is a numbered judgment call, recorded for post-hoc audit and reversible at plan time.)*

- **A1 — Binary Snap for Sidebar Toggle.** SHELL-03 accepts a binary snap (0px ↔ 240px) without CSS transitions because GPUI does not support CSS animations out of the box.
- **A2 — Settings Button in Sidebar Footer.** `fe/src/components/layout/AppSidebar.tsx:141-152` renders a pinned "Settings" button in the sidebar footer. Although Settings is fully built in Phase 6, Phase 2 includes this footer row to preserve 1:1 sidebar geometry.
- **A3 — Native Directory Picker via GPUI Built-in API.** `CreateSessionDialog` directory browsing uses `gpui-pre`'s `App::prompt_for_paths(PathPromptOptions { directories: true, .. })` directly rather than external crate `rfd`, keeping binary size small and avoiding duplicate dialog engines.
- **A4 — Pane Row Formatting.** Pane sub-rows display `{pane.current_command || pane.title || pane.id}` preceded by a 4px circular dot, matching `AppSidebar.tsx:120-130`.
- **A5 — Session Badge Copy Format.** In the sidebar, session window count renders as a raw integer `{node.session.windows}` (e.g. `2`), whereas in `SelectSessionView` grid cards it renders with a `w` suffix `{node.session.windows}w` (e.g. `2w`), matching exact FE lines (`AppSidebar.tsx:109` vs `SelectSessionView.tsx:51`).
- **A6 — Inline Error in Dialog.** FE uses `toast.error` for creation errors, but GPUI toast system is scheduled for Phase 7 (STATE-03). In Phase 2, backend rejections are surfaced as an inline error banner inside the dialog to guarantee immediate user feedback.
