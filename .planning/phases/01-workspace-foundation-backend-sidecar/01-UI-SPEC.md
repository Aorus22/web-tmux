## Phase Surfaces

### S1 — Minimal title bar (visible in every status; requirement SHELL-02)

- Full-width bar, height **44px**, background `#1e1e1e`, bottom border 1px `#3c3c3c` (FE `border-b` on `bg-background/80` — over a `#1e1e1e` body the 80% backdrop-blur blend renders as `#1e1e1e`; GPUI has no backdrop-blur, use solid — Assumption A9), horizontal padding 12px.
- **Left group** (gap 8px): `TerminalSquare` lucide icon 16px at muted `#808080`, then label **"Tmux GUI"** — Body 14px/500, `#d4d4d4`. (Sidebar toggle button = Phase 2; window tabs = Phase 3; Settings gear = Phase 6.)
- **Right group**: vertical separator line (1px `#3c3c3c`), offset **4px** from the preceding content (`ml-1`, FE AppTitleBar.tsx:85) with **4px** padding to the first button (`pl-1`, same line) — both on-grid `xs`; then three adjacent icon buttons, each **40×32px**, radius 6px, no gap:
  - Minimize: `Minus` icon 16px; **Maximize/Restore**: `Square` 14px when restored, `Copy` 14px when maximized (icon set swaps by actual window state via `IsZoomed` — web-term `window_state::is_window_maximized`); **Close**: `X` icon 16px.
  - Icon stroke width 1.5; idle icon color `#9d9d9d`; hover: background `#2d2d2d` + icon `#d4d4d4`; **close hover: background `#7F1D1D` + icon `#ffffff`**.
- **Drag contract**: the whole header is a drag region (GPUI: `window.start_window_move()` on mousedown of the bar background — web-term `tab_strip.rs` pattern); the three control buttons opt out (they handle their own mousedown, no window move). Double-click on the bar toggles maximize/restore via `window_state::toggle_maximize`.
- Window frame: `TitlebarOptions { appears_transparent: true, title: Some("Tmux GUI") }`; Windows DWM dark-frame block (`DwmSetWindowAttribute` attrs 20/19) ported verbatim from web-term `main.rs:69-90` — no white flash on maximize.
- Tooltips: native `title` semantics of FE buttons (Minimize / Maximize|Restore / Close) render as gpui-component Tooltips or deferred to Phase 3 title-bar parity if the stock Tooltip look diverges (documented in Assumption A7).

### S2 — Starting page (`BackendStatus::Starting`; requirement STATE-01)

- Fills the workspace area below S1; centered flex column, gap 12px, padding 32px, background `#1e1e1e`.
- Spinner: lucide `Loader2` SVG constant, 20×20px, color `#808080`, rotating 360° every **2s linear, infinite** (Tailwind `animate-spin` parity — override gpui-component Spinner's 0.8s ease_in_out default; `Spinner::new().icon(Icon::path(LOADER2_SVG)).color(#808080)` wrapped in a 20px box, or the equivalent inline gpui `Animation`).
- Text: **"Starting backend…"** — Label 12px/400, `#808080`. Nothing else on the page (no subtitle line — FE parity).
- Rendered while the sidecar warms up (spawn → `BACKEND_PORT:<n>` stdout handshake → `/api/health` probe ok). The 10s port timeout must land on S3, never a perpetual spinner (Electron's `backendTimedOut` wart is corrected, not ported).

### S3 — Failed-backend page (`BackendStatus::Failed { reason, stderr_tail }`; STATE-01)

- Page: background `#1e1e1e`, foreground `#d4d4d4`, padding 32px, content centered vertically; card fixed max width **700px**, padding 24px, background `#2d2d2d`, border 1px `#7F1D1D`, radius 8px (web-term `status.rs` card structure, web-tmux tokens). Long content scrolls the page, not the card (overflow-y on the page area).
- Heading: **"Backend Startup Failed"** — Heading 16px/500, `#d4d4d4` (Assumption A2 documents the contrast-based choice away from web-term's red text).
- Reason: **`Reason: {reason}`** — Body 14px/400 `#d4d4d4`, margin-top 8px, wraps on long reasons.
- stderr tail block (margin-top 16px): padding 12px, background `#1e1e1e` (darker inset on the card), border 1px `#3c3c3c`, radius 6px; JetBrains Mono 12px/400 `,#d4d4d4`; **newest 10 lines only** (web-term ring-of-10 parity), each line its own wrapping line block; secret-pattern redaction per Assumption A4. If the tail is empty (immediate exit), the block is omitted entirely — reason alone.
- Footer (margin-top 24px, justify-end, gap 12px):
  - **Quit** — outline style: background `#1e1e1e`, border 1px `#3c3c3c`, text `#d4d4d4` 14px/500, radius 6px, padding 8px 16px, cursor pointer; hover background `#3c3c3c`. Action: kill sidecar child if alive, then `cx.quit()` — no confirmation.
  - **Retry** — primary: background `#d4d4d4`, text `#1e1e1e` 14px/500, radius 6px, padding 8px 16px, cursor pointer; hover background `#c5c5c5`. Action: reset to Starting (S2), tear down anything of the prior spawn, re-run the complete handshake; the 10s timeout applies again and repeated failures re-render S3 with fresh reason/tail.
- No Crashed variant: `BackendStatus` for web-tmux is `Starting | Ready | Failed { reason, stderr_tail }` (early-exit folds into `reason`, e.g. `backend exited early (code 1)`) per 01-CONTEXT.md; web-term's `Crashed` variant is not ported.

### S4 — Ready shell (`BackendStatus::Ready`, Phase 1 end state)

- Title bar (S1) stays; workspace body renders as a plain `#1e1e1e` surface with no placeholder content. Sidebar/errors/workspaces arrive Phases 2–3; there is no Phase 1 "success message" (extra copy would break the later 1:1 parity).
- Geometry: default window **1200×800**, minimum **800×500** (web-tmux `desktop/main.js:184-188` — NOT web-term's 1160×660/960×540), persisted geometry restored at boot before open (web-term `window_state::restore`), observe + debounced save on move/resize/maximize.

## Interaction Contract (Phase 1 state machine)

1. Launch → window opens at persisted (or default 1200×800) size → S1 + S2 while supervisor warms up.
2. `BACKEND_PORT:<n>` parsed + `/api/health` ok → S4 (title bar persists, body clears).
3. Spawn failure / early exit / **10s port timeout** → S3 with reason + tail.
4. Retry on S3 → back to S1+S2 (full re-handshake; repeated failures re-render S3 fresh).
5. Quit on S3; Close control on either page → kill sidecar if alive → exit app.
6. Minimize / Maximize⇄Restore / drag / double-click drag-region at any status (S1 contract).
7. No keyboard shortcuts, no toasts, no dialogs in Phase 1 (Palette/DLG are Phase 5–6; toasts Phase 7).

## Assumptions

*(User is away; discuss decisions were auto-accepted. Each is a judgment call by this agent, recorded for the post-hoc audit and reversible at plan time.)*

- **A1 — Title-bar identity included in Phase 1.** CONTEXT.md says Phase 1's bar is "drag region + custom min/max/restore/close"; this spec also renders the static left-side identity (TerminalSquare icon + "Tmux GUI" label) because it is content-free parity (SHELL-01 anatomy), requires zero controls, and a fully empty 44px strip would look broken. Sidebar toggle (Phase 2 / SHELL-03), window tabs (Phase 3), Settings gear (Phase 6) are explicitly not rendered. Dropping identity is a no-op if the planner disagrees.
- **A2 — Failed-page styling.** No FE anchor exists (Electron FE has no failed-backend page; it warts at "Loading…" — the 10s timeout handling is corrected by STATE-01 rather than ported). Structure = web-term `status.rs` (its working Retry/Quit + redact pattern), palette re-based on default-dark tokens. Heading rendered in foreground `#d4d4d4` rather than destructive red: default-dark's `#7F1D1D` text on `#2d2d2d` fails legibility; the destructive role stays visible via the card border + close-hover fill (same tokens FE would use). Same reasoning retitled sizes from web-term's `text_xl` to FE's Heading/Body rhythm.
- **A3 — Retry = primary-filled.** FE's only existing Retry (ErrorState) is an outline button, but that is a downstream state's affordance; on the failed page Retry is the single CTA, so it takes the `primary`/`primaryForeground` fill (this is also what web-term's working page does, re-colored). Quit stays outline.
- **A4 — Stderr redaction policy.** CONTEXT.md requires a "redacted stderr tail". The web-tmux spawn env carries no secrets (only `TMUXGUI_HOST`/`TMUXGUI_PORT`), so the redactor is defense-in-depth: mask the values of any line matching env/secret key patterns (`(?i)(key|secret|token|password)`) with `[REDACTED]`, keep newest 10 lines (web-term cap). Documented so the parity audit doesn't "discover" it.
- **A5 — Window geometry numbers.** Default 1200×800 / min 800×500 come from web-tmux's `desktop/main.js`, NOT web-term's GPUI defaults (1160×660 / 960×540 min 960×540) — geometry must match the ported app.
- **A6 — Ready body intentionally blank.** No "add session"-style teaser: Phase 2 owns the populated/empty/error pages (STATE-02). Blank body avoids copy that Phase 2 must delete.
- **A7 — Title-bar button tooltips.** FE sets native `title` tooltips; gpui-component Tooltip exists but stock styling may diverge from Phase 3's title-bar parity work. Checking them with `tooltip` from the inventory is in-contract; a deferred plain-label tooltip is an acceptable interim.
- **A8 — No live spinner-with-caption pairing beyond FE.** web-term's status page adds a secondary caption line ("Initializing Go server…"); the FE has only spinner + text, so the extra line is dropped.
- **A9 — `bg-background/80` + backdrop-blur ≈ solid `#1e1e1e`** in Phase 1 because the only content behind the bar is the `#1e1e1e` body; the translucent-over-content effect only becomes meaningful once panes/tabs render (Phase 3+), where the chrome-parity phase decides the translucency port.
