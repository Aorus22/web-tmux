<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| App -> Go Sidecar (Loopback) | IPC and HTTP requests over 127.0.0.1; local process boundary |
| App -> Settings Filesystem | Stored JSON configuration in OS user profile directory |
| Sidecar -> Local Environment | Process environment variables and child stdio streams |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Information Disclosure | `webtmux-supervisor::SpawnOptions` | high | mitigate | Empty argv for child process; no secrets passed in command-line arguments visible in process listings |
| T-01-02 | Elevation / Network Exposure | `webtmux-supervisor` environment | high | mitigate | Hardcode `TMUXGUI_HOST=127.0.0.1` in spawn environment to prevent binding sidecar to 0.0.0.0 |
| T-01-03 | Tampering / Session Hijacking | `webtmux-supervisor::SpawnOptions` | medium | mitigate | Explicitly strip `TMUX` and `TMUX_PANE` from child environment using `env_remove` so nested tmux sessions do not hijack execution |
| T-01-04 | Information Disclosure | `webtmux::views::status` (stderr tail) | medium | mitigate | Redact sensitive patterns (`(?i)(key\|secret\|token\|password)`) to `[REDACTED]` before rendering stderr tail on Failed page |
| T-01-05 | Denial of Service | `webtmux-supervisor` process management | low | mitigate | Set `kill_on_drop(true)` on child process and implement `adopt_or_clear` to detect and recover orphaned sidecar instances |
| T-01-SC | Tampering | Cargo dependencies | high | mitigate | Exact `=` dependency pins in `Cargo.lock` committed as first artifact; vetted against crates.io legitimacy audit |
</threat_model>
